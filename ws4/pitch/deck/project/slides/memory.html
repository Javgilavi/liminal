And a memory over FLUX's own features tracks the task stage at 0.90, against 0.54 without memory. A GRU gets 0.87, so the memory matters, not TTT itself. Simulation only." Do not imply TTT alone makes the difference. If asked why TTT: its case is constant-size state over long contexts, and our episodes are too short to show it. If asked about failure: on FLUX's failed sim rollouts, monitors trained only on demos said "in cup" on 43 % (GRU) and 37 % (TTT) of re-plans; 12 failed rollouts in training fixed it (robottt_flux.md 11.12). The real chain uses Claude Haiku checks (97.1 % put, 98.2 % take on recorded Haller frames). Bars are to scale (600 px = 1.0); both FLUX-feature memories share one colour on purpose. Repeated-stage accuracies in brackets in the source: FLUX none 0.15, GRU 0.74, TTT 0.80; frame none 0.39, GRU 0.62, TTT 0.70. Features from 21 sim episodes, 1,250 re-plans, 0.82 s each on the pod. The memory has no motor authority: it only reports progress to the orchestrator.
