Connect the public lab to your local robot

GitHub Pages serves static files. A local research companion reads the Haller controller’s measured telemetry and existing camera snapshots. It does not open another serial or camera device. 

# In the Liminal source checkout with the research UI changes:
uv pip install --python .venv/bin/python -e '.[research]'
./scripts/research_ui.sh \
  --profile configs/policy/official_haller_right.yaml \
  --site-url https://javgilavi.github.io/liminal/

Keep the existing Haller controller running locally on port 8000. Use the appropriate verified profile for the actual active arm, checkpoint, units and camera assignment; the example profile selects the right arm and a base-policy checkpoint. It is not the RAW-5k adapter shown in the archived successful videos. The lab shows the active checkpoint label after pairing.

  1. In the full-screen lab, select Pair local robot.
  2. Open the local pairing page at http://127.0.0.1:18003/pair.
  3. Use its private link to return to the public lab. The one-session token is carried in the URL fragment, removed by the lab and retained only in memory. It is not sent to GitHub.
  4. Allow local-network access if your browser requests it. The page must run on the same machine as the loopback companion; use a local SSH tunnel when appropriate.

Observation-only is the default. Sending actions additionally requires fresh telemetry, a verified profile, and MANUAL mode plus torque engaged through Haller. The lab does not engage torque or clear STOP. Stop this trial cancels the trial started by this companion; Haller remains the hardware stop interface. Disconnecting the browser does not stop a local trial.

Trials save locally under runs/research/ with the existing runner’s observations, actions and reports. No telemetry, camera stream or recording is stored on GitHub Pages. The two-arm viewer mirrors measured joints; live objects and contact forces are not tracked.
